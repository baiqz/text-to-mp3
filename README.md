# 文字转 MP3（浏览器版 · 字数不限）

把任意长度的文字转成 MP3。

**不需要安装任何东西，也不需要服务器** —— 打开网页就能用。所有切分、合成、拼接都在你自己的浏览器里完成。

## 在线使用

**<https://baiqz.github.io/text-to-mp3/>**

- 把文字粘进去（或直接拖一个 `.txt` / `.md` 文件进去），点「开始转换」，然后播放、下载。
- 也可以把仓库里的 `index.html` 存到自己电脑上双击打开（合成时需要联网）。

## 它是怎么做到「不限字数」的

服务端一次只接受一小段文本，所以长文会被自动切开、分别合成为音频，最后拼成一个完整文件。

三个关键点：

**1. 切分不切断句子。** 严格按 `段落 → 句末标点（。！？…） → 停顿标点（，、：）） → 空格 → 硬切` 逐级递降。在句子中间断开，合成语音的语调会直接"摔在地上"。

**2. 拼接是帧级的。** MP3 不能随便拼字节：某一段若带着 ID3 标签或结尾有半个残帧，拼进去会让解码器错位，表现为杂音、时长变短甚至整个文件打不开。程序对每段先做帧级体检（跳过标签、按帧长逐帧前进、丢弃尾部残帧），只输出干净的连续帧流。

**3. 失败不拖垮整体。** 每段独立重试 3 次；并发 3 路同时合成；某段彻底失败只记录并跳过，其余照常输出。

### 实测数据

| 输入 | 分段 | 产出音频 | 文件 | 耗时 |
| --- | --- | --- | --- | --- |
| 332 字 | 1 段 | 56 秒 | 328 KB | ~1 秒 |
| 864 字 | 6 段 | 2 分 17 秒 | 0.79 MB | 3.3 秒 |
| 9,989 字 | 27 段 | 36.8 分钟 | 12.65 MB | 23.6 秒 |

约 40~90 倍速。实际能处理多长只取决于浏览器内存——几万字没问题。

## 功能

- **323 个音色 / 142 种语言与地区**：中文 15 个（普通话 7、辽宁话 1、陕西话 1、粤语（中国香港）3、国语（中国台湾）3），另有英语、日语、韩语等；支持关键词搜索。
- **按类别筛选**：「中文 / 方言 / 多语言 / 其他语言」一键切换，列表可「显示更多」一路翻到底，不是只给你看前几条。
- **一键风格**：深夜电台、纪录片解说、新闻播报、睡前故事、活力带货、童声朗读、粤语旁白等 8 组预设，把「音色＋语速＋音量＋音调」配好，点一下即可。
- **语速 / 音量 / 音调** 可调。
- 直接读取 `.txt` / `.md` 文件，或拖拽进文本框。
- 实时进度、随时取消。
- 成品可直接在页面播放，或下载为 MP3（自带标题标签）。
- 设置会记住，下次打开还是上次的选择。

## 音色为什么只有这些？（一段实测记录）

这套音色的边界是**用真机一个个试出来的**，不是抄文档：

- 官方声库接口（`voices/list`）返回 **322 个 / 中文 14 个**，这是接口的硬上限。
- 我们额外试了大约 170 个"接口清单里没有、但理论上可能存在"的音色 ID（Azure 的方言音色、多语言音色、Dragon HD 音色、老一批已下架的中文音色，以及各种写法变体）。结果是：**清单外只有 1 个中文音色真的能用**（`zh-CN-XiaoxuanNeural` 晓萱），其余全部被服务端明确拒绝。
- 也试过用 SSML 的 `mstts:express-as` 打开**情感风格**（一个音色变十几种语气）。服务端直接回 `SSML is invalid`，三种命名空间写法都被拒，这条路走不通。
- 所以：**想要更多中文音色，只能换引擎**（例如接入 Azure 官方语音服务，需要你自己的密钥——那里云泽、晓墨、Dragon HD 等音色都还在）。

## 两个踩过的坑（代码里都已处理）

**音色会悄悄下架，清单也会漏报。** 服务端的声库里挂着某个音色，不代表它还能用——比如 `zh-CN-YunzeNeural`（云泽）、晓墨、云枫这一批中文音色已经从声库消失，但用它合成时服务端不会报"找不到音色"，只是一段段地返回空音频，用户看到的只是"全部失败"。反过来，清单里没有的音色也可能仍然能用。所以：

- 音色清单以服务端实际声库为准，并叠加两张**实测纠偏表**：确认下架的一律剔除，确认清单外可用的照常列出（列表里标「扩展」）；
- 万一还是选中了不可用的音色，服务端会明确回一句 `Unsupported voice`，程序立刻换成默认音色并把原因告诉你，而不是让整批失败。

**音频报文的头部偏移。** 服务端返回的二进制报文是 `[2 字节头长][头部文本][音频帧]`，音频从"头长 + 2"开始。少切或多切 2 个字节，整帧就废了——但帧结构看起来仍然是"干净"的，帧级校验抓不到，只有交给真正的解码器才会露馅。测试里专门用浏览器原生解码器读时长来兜这一条。

## 需要更强的版本？

本仓库的 `local/` 目录里是**完整版**（Python + 本地服务）：

- 支持直接读取 `.docx`（无需安装 Word 或转换工具）
- 全部 323 个音色可搜索、带中文名与风格说明
- 转换历史记录、随时回看下载
- 内置**网络诊断**（分层检测：域名 → 端口 → 加密连接 → 代理 → 真实试合成），双击 `诊断.bat` 即可
- 文本长度上限极高，长文合成速度更快

用法：进 `local/`，双击 `start.bat`（首次会自动装依赖，需本机有 Python 3.10+）。

## 开发

```bash
node tools/build.js            # 重新构建 index.html
node tests/test_token.mjs      # 令牌算法（40 项）
node tests/test_split.mjs      # 切分器（103 项）
node tests/test_mp3.mjs        # MP3 帧处理（42 项）
node tools/browser_probe.mjs tests/browser/engine.html    # 引擎回归（20 项）
node tools/e2e_app.mjs         # 真实浏览器跑完整流程（40 项，会真的合成音频）

# 对线上网址跑同一条端到端流程（证明"部署出去的那份文件真的能跑"）
E2E_LIVE_URL=https://baiqz.github.io/text-to-mp3/ node tools/e2e_app.mjs
```

改了 `src/` 下的任何东西，都要重新跑 `build.js` 并把生成的 `index.html` 一起提交——Pages 不做构建。

### 关于 `token.js`

程序需要向服务端出示一个访问令牌。这个令牌的摘要算法是经过改写的（常量表与初始状态都被换过，与标准 SHA-256 结果不同），所以不能简单地用 `crypto.subtle` 代替，必须照原样实现。`tests/test_token.mjs` 用 Python 参考实现生成的向量做逐字节比对，确保两个实现完全一致。

## 说明

- 用到的语音接口就是 Edge 浏览器「朗读」功能所用的接口，页面直接连它，不经过任何第三方服务器。
- 文字会被发送到微软的语音服务用于合成；除此之外不收集任何数据，音频也不会被上传。
- 合成时必须联网。如果哪天整体都失败，通常是接口调整了校验方式，欢迎提 issue。
